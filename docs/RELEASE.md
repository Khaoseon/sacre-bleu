## Implementation decisions

- `OFF_USER_AGENT` is server-only operator configuration. The generator requires an explicit identity and the shared validator checks a bounded app/version and HTTPS public contact URL. Absent overrides retain the original production identity exactly; malformed/empty overrides disable upstream lookup. Auth, RLS membership, JWT verification, origin restrictions, shared budget, fixed upstream endpoint, response limits and manual fallback stay intact. See [INSTALL](INSTALL.md) and [OFF](OPEN_FOOD_FACTS.md).
- Code/documentation MIT and the creator's MIT artwork notice are separate. The generated deployed notice bundle includes both notices and the existing 25 reviewed runtime dependency sources. OFF database/content/image licenses remain separate, with provenance and links intact. No runtime dependency was added or upgraded.
- Package version 1.0.0 is preparation, not evidence of a released/deployed version. Existing storage keys, Supabase local project ID, RPCs, historical hashes/links and the legacy OFF default retain their identities. A repository rename does not require changing app origins, Auth callbacks, CSP, backend references, PWA scope or caches.
- CI uses pinned actions, read-only repository permissions, no persisted checkout credentials, fictitious public build settings and disposable local backend fixtures. OFF browser and two-scanner regression journeys join existing checks. There is no `pull_request_target`, deployment or release step. Historical compatibility still needs full Git history and commit `9eca5d11a42d8839d822f56dadc9fbbb7aa6c801`; a future history rewrite must preserve or intentionally replace that evidence and rerun compatibility tests.

## Ordered publication runbook (separate approval required)

1. **Resolve the privacy blocker while private.** Review the original XMP locally with the affected creator/maintainer. Record explicit consent to disclose the historical fields, or separately authorize a coordinated history/PR-cache remediation plan. Deleting the current file or a branch is insufficient. Do not publish first and sanitize later. If rewriting, account for old clones/forks/PR refs, preserve compatibility evidence and rerun the full pipeline; this PR does not authorize it.
2. **Final private review and merge decision.** Review exact head/diff, audit any new PR content, confirm both CI jobs pass on the exact head and check no source/maps/env/backup files entered output. Review the release notes draft below. Reconfirm Pages Preview deployments are disabled and production-only variables/bindings cannot reach PR builds. Keep `[CF-Pages-Skip]` on review commits and on the eventual merge/squash commit if deployment is unwanted. A PR title/label alone is insufficient; inspect the actual Pages skipped entry. Merge only under separate explicit authorization. No SQL migration or Edge redeployment is needed merely to publish the source.
3. **Protect main for a solo maintainer.** Use a main ruleset requiring PRs with **zero required approving reviews**, required checks **Application et PWA** and **Restauration, sécurité et hors ligne**, and up-to-date branches. Block force-pushes and deletion; apply enforcement to administrators without a routine bypass. Require conversation resolution. Do not require CODEOWNER approval, a second reviewer, signed commits, deployment checks or a merge queue. If using classic protection, ensure the UI can require the PR path without requiring an approval; prefer a ruleset for that distinction. Private-plan availability may require applying protection immediately after visibility changes; keep merges frozen during that window. Do not require the Pages check, which can be absent on skipped builds. [GitHub protection guidance](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches).
4. **Prepare security and contribution settings.** Review Actions secrets/environments and GitHub App access privately, without copying values into a report. Keep default workflow token read-only and do not send secrets/write tokens to fork PRs. Require approval for all outside-collaborator workflows; inspect changes before approving execution on GitHub-hosted runners. Enable Issues and retain lightweight PR guidance/no support promise. Prepare private vulnerability reporting and maintainer notifications; it is available for public repositories, so if unavailable while private, enable immediately after step 6. Verify the reporting button and notification delivery with a harmless coordinated report, never exploit details in Issues. [Private reporting configuration](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository), [fork workflow review](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/approve-runs-from-forks).

## V1.0 release notes draft (not published)

Sacré bleu is a personal pantry PWA for two confirmed accounts. French and English settings accompany whole-package stock, EAN/UPC scanning with manual fallback, a shared shopping list and editable Open Food Facts suggestions. PostgreSQL serializes authorized shared changes; request identities support recovery without double application, and stale corrections are refused. The app offers read-only offline access, JSON export and owner-only transactional replacement.

Independent operators use their own Supabase/Cloudflare resources and configurable OFF identification. Code/documentation are MIT; mascot by Eloane ROURE is redistributed with permission under its own MIT notice. Bundled libraries and OFF data/images retain separate licenses. Issues and focused PRs are welcome without guaranteed maintenance/support.

Limits: no offline writes, private photo uploads or password recovery UI; browser cache/JSON exports are unencrypted. No second independent hosted installation or new physical-device campaign was performed for this release preparation. Screenshots and redesign are deferred to V1.1. Public source does not make any running pantry public.
