## Browser campaign

`npm run test:7a:browser` runs the new convergence verifier. The older verifier is retained as `verify-7a1.mjs` for historical reference, while CI's existing script now runs the broader active-proposal regressions. `--checks-only` is a local debugging option that skips screenshot-matrix regeneration; the delivery validation runs the **full** command.

Actual Chrome captures cover **320 × 568, 320 × 812, 375 × 667, 375 × 812, 390 × 844, 430 × 932 and 900 × 932**. At each size: both inventories, both details, editor, shopping/check state, ready/result scanner, offline, empty, mixed imagery and long name; additional narrow-width warning and 7A.1 comparisons. Reduced editing height is 460 px. English, error, unknown Remove, attribution/photo, replenishment, continuous swipe and full side-by-side comparisons are additional captures. Clean visual fixtures precede destructive regression interactions. Old 7A.1 screenshots remain in their original directory.

Tests also cover all shopping controls/free-versus-linked semantics, nonoptimistic multi-quantity confirmation, photo over 500 KB/replace/remove/unsupported HEIC, current-page draft guards, actual touch photo swipes/tap arbitration, short/flick/diagonal/vertical/cancel/sheet/pending gestures, and 100/300-product catalogues. The 24 px edge guard is tested with DOM touch events to assert it does not capture them: a real browser-native edge back is deliberately not suppressed by the application and must not be confused with a page-navigation failure. Native iOS system gestures still require a device.

All requests in the test context are observed and non-loopback origins blocked/asserted absent. No localStorage/sessionStorage writes or service worker registration. Normal `dist/assets` is scanned for prototype code, fictional brands, fonts and image assets. Source diff additionally verifies no changes since 7A.1 in model/storage, application/scanner/backend, root Vite config, CI, dependencies or lockfile.

## Deployment safeguards and limits

The first remote 7A.2 campaign caught a runner-dependent fast-flick test: a two-event gesture could take longer than its intended fast duration across CDP calls. Velocity now uses native touch-event timestamps, rather than handler-execution time, and the recorded browser flick supplies a 60 ms event timeline. Slow/short/diagonal rejection and the existing speed/distance thresholds remain unchanged. This improves input-time measurement; it does not claim Safari/device calibration. After this event-time correction, the complete local interaction journey passed with --checks-only; the unchanged seven-size visual matrix had passed after the long-name layout change. The corrected head repeats both in the existing full CI.

PR #9 starts open/unmerged, head feature branch, base release/v1.1 at `b0a39713f3fb73a55d9fdb90f01a03d77ec14205`. Workspace initially clean at the requested baseline. No force push, reset, branch protection change, release/tag, deployment command, hosted Supabase call or migration.

The [original read-only Pages observation](../SAFETY.md) was main production / previews None. A fresh whole-window dashboard capture was rejected by automatic approval review because unrelated private tabs could be exposed. No bypass or settings modification was attempted; a fresh signed-in Pages settings/deployment-history audit is **unverified**. The safe alternative is feature-only publication with **`[CF-Pages-Skip]` at the start of every new commit message**, which Cloudflare documents as omitting that deployment without configuration changes. [Official GitHub integration / skip-prefix contract](https://developers.cloudflare.com/pages/configuration/git-integration/github-integration/). No Pages check is expected when skipped; absence alone is not an independent dashboard audit.
