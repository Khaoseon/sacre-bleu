## Private-photo security, backup and production gates

**Private photographs are stored in PostgreSQL (`bytea`), limited to 40 photos / 20 MB per reserve, and are not included in ordinary JSON export.** There is no Storage bucket or portable photo archive. JSON export/restoration with any private/legacy reference remains refused. Offline inventory stores opaque references, never private image bytes; reads require current online membership. Previously viewed pixels and historical WAL/backups cannot be remotely erased.

## Recommendation and remaining limits

**GO for maintainer review of this feature branch; NO-GO for production release now.** Local evidence supports the integrated behavior and the three corrections. Required release blockers are completed physical camera/mobile/PWA and VoiceOver/TalkBack acceptance, separately authorized hosted photo/security/update smoke checks, and backup capacity/full recovery acceptance. The maintainer also handles GitHub CI review; this task never waits for, polls or monitors Actions.

Known limits remain: HEIC requires conversion; metadata/initial scan and subsequent photo save are separate confirmed steps (a rejected photo can leave saved metadata/stock); private photos are online-only and nonportable; narrow enlarged layouts need scrolling; real optics, OS download persistence, safe areas and installed-worker lifecycle need physical evidence. No architecture rewrite, multi-unit stock feature, deletion undo or new photo archive was introduced. Package version/tagging remains unchanged for the maintainer's release process.
