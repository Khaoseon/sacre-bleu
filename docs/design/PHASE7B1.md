# Phase 7B.1 — production design foundations

Scope: prepare the approved 7A visual foundations in the real application, without rebuilding screens or changing workflows. [Final 7A decisions](phase7a/final/README.md) take precedence over the earlier convergence recommendations: photographic shelf by default, optional compact inventory and object-led detail remain future integration work.

## Architecture and adoption

`src/style.css` imports `src/ui/foundations.css` after the existing theme palettes. The `--sb-*` namespace supplies semantic colors, font families/sizes/leading, a 4px spacing scale, control/surface/pill radii, 44px targets, focus, elevation and motion. Existing `--canvas`, `--green`, etc. retain their values and consumers. No global font, layout or palette replacement is made.

Light mode exposes approved warm paper, blue ink/brand and readable status colors through the new tokens. Auto still resolves through the existing light/dark mechanism. Dark, slate, retro-cream and retro-petrol inherit their current semantic equivalents through an adapter to the existing theme variables. Storage identifiers, appearance selection, failure handling, system observation, cross-window synchronization and early bootstrap stay unchanged. Future themes can override semantic tokens without changing component implementations; a separately approved dark blue palette can replace the adapter later.

Use `.sb-foundation` on a migrating region, `.sb-title` for Fraunces headings, `.sb-surface` for paper surfaces and native `<button className="sb-button">` for primary actions (`data-variant="secondary"` for secondary). `.sb-focus` supplies keyboard focus for other native controls. These small CSS primitives preserve native semantics without wrapper components or a generic variant framework. Caller code supplies translated labels through `src/i18n`, actual disabled/pending state and confirmed-write feedback. Use `--sb-text-input` for future fields to retain at least 16px input text. No existing screen adopts these classes yet.

Only the reusable image primitive is wired into the existing `ProductImage` adapter. `ProductMedia` handles lazy/async decode, contain-fit, no-referrer requests, missing/failed-image fallbacks and source changes (including retrying A after A → B → A). Existing category icons, personal-photo priority, OFF URL validation and attribution remain with the existing adapter/callers. Empty alternative text prevents duplicate announcements alongside product names; standalone consumers must supply a localized meaningful `alt`. Source content is never translated. A neutral square frame is available to new consumers; existing `.product-image` dimensions/category colors still override it. No crop editor, image upload, private photo storage or fixture imagery is added.

Production fonts are local WOFF2, **92,044 bytes total**, with OFL notices and [reproduction instructions](../../src/assets/fonts/README.md). Existing screen fonts remain unchanged; font faces become active as regions migrate. The existing PWA rule includes WOFF2 assets, without changing update behavior.

## Validation and next phase

The existing theme suite also checks semantic text/status contrast (4.5:1) and control/focus contrast (3:1) for all five resolved palettes. `node scripts/browser/foundations.integration.mjs` checks local font loading, a 320px layout, unchanged legacy typography, all resolved themes, keyboard focus, 44px controls, reduced motion and actual missing/broken/retried media. It uses only synthetic local images and produces no 7A screenshot collection.

Local results: 87 focused Vitest tests passed (`theme`, `App`, `i18n`, `productInfo`); the focused Chrome foundations check passed, including the legacy image adapter's 36 × 44px mobile frame. `npm run typecheck`, `npm run build`, `npm run format:check` and `git diff --check` passed. The build retains its existing >500 kB main-chunk warning. Font conversion verified identical character maps and actual 400/600 weights. No complete database/backend/browser matrix was run; remote CI is not monitored as part of this delivery.

7B.2 must adopt foundations region by region, preserve receipt/current-snapshot behavior and design each screen's responsive composition. Existing zero-stock image dimming belongs to the old screen stylesheet; the neutral primitive adds no filter. Review that screen styling when migrating photographic shelves so package labels keep their colors. No new multi-unit RPC, undo compensation, navigation, scanner, replenishment or photo workflow is implemented. Device/PWA, screen-reader and physical mobile acceptance remain later work. No backend/database test campaign, migration, hosting action, merge or deployment is included.
