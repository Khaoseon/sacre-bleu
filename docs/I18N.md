# French and English interface (Phase 6C)

## Architecture and contributor rules

`src/i18n/catalog.ts` owns paired French/English messages. French source strings are stable presentation keys: this preserves the existing service-message vocabulary, including labels in already saved pending intentions. Every entry has both languages; `t()` accepts only catalogue keys and requires the interpolation slots in its key. Tests check nonempty translations and identical slots. `src/i18n/plurals.ts` owns plural forms; `Intl.PluralRules`, `Intl.NumberFormat` and the selected locale (`fr-FR`/`en-GB`) determine display formatting.

This is a small, dependency-free presentation module, with one observable language preference and `useSyncExternalStore`. `Root`, the standalone demo `App` and update hosts subscribe without changing component identity. There is no language-dependent React key, page reload, new authentication request or business-rule branch. Independently mounted future UI roots should subscribe with `useLanguage()`.

To add interface text, add a complete `{ fr, en }` catalogue entry and use `t('French source key')` at render time. Interpolate with numbered slots, for example `t('Modifier {0}', { 0: product.name })`; React still escapes the result. Use `deferred()` for notices containing values which must survive a language change, then resolve with `message()` when displayed. Numbers passed to interpolation are display-formatted; pass barcodes/identifiers as strings. Keep complete sentences together where grammar requires it. Add plural entries for counted phrases, and test zero/one/many. A future language requires adding its form to every entry and plural family, extending `Language`, its locale and the explicit selector/validation; there is no browser-language detection or remote translation service.

`label()` is restricted to controlled categories, units, navigation and theme labels. Never pass product names, reserve names, brands, shopping text, provider metadata or arbitrary strings to it. Option `value` and React keys retain the original identifiers.

Business modules, storage, Auth, RPC adapters and the camera controller retain their existing messages and classification. `message()` is an exact allowlist at the presentation boundary, rather than a translation of arbitrary server errors. SQLSTATE/Auth classification still happens in the existing adapters. The known created-product recovery suffix is composed separately. Unknown details produce a generic translated error in either language. The source audit test protects service-message coverage; no translation module is imported by these services. Adding a new service message requires adding its exact presentation key. This intentionally avoids rewriting existing recovery-journal formats or changing error behavior to implement localization.

## Device preference and metadata

Settings expose **Français** and **English**, with native language tags, before sign-in, in demo mode and in a shared pantry. French is the default even on an English browser. Only `app-reserve.language.v1` in localStorage is written. The setting survives reload, installed-app restart and signout; it never enters account metadata, the pantry, Auth keys, private snapshots, backup JSON or sessionStorage intentions. Existing open windows keep their selected language until their own selection or reload. Missing, invalid or inaccessible storage falls back to French at startup. A failed write keeps the selection for the current session and announces that persistence failed.

The selected language updates `html.lang`, the document title and description immediately. The name Sacré bleu and Apple app title remain the brand. The static PWA manifest intentionally retains French language/description and its existing name, scope, start URL, icon set and cache/update contract. Installed OS metadata may remain French; replacing a live manifest to follow a device setting would add install/update risk. Native browser validation, permission sheets and OS settings follow the browser/OS language. The app itself translates its own validation, labels and explanations.

## Compatibility and validation

No schema, generated database type, SQL enum, RPC argument, Edge authorization, Auth storage format, theme key, backup field/version or private/offline journal changed. Zero-stock retention, integer rules, confirmed-write feedback and pending intention UUIDs remain in the existing business layer. Existing French pending labels are resolved when displayed, including after switching language; the serialized intention is unchanged. No new runtime dependency or external request is added.

The selector uses a native select with an explicit translated accessible name, native-language options, the existing select styling and the existing touch target. It does not remount dialogs or forms. Responsive checks exercise both languages at 320px, and English restore previews at 320/390px. Physical Android/iOS camera, screen reader, keyboard and installed-PWA acceptance remain manual; browser simulations do not certify those devices. Screenshots, artwork and redesign remain deferred.
